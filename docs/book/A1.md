# A1 · The five pieces: MCP, RAG, memory, evals, harness

**Denotes.** An agent that works is five pieces, and each one exists to cover a specific lack: a model alone cannot act, does not know your corpus, forgets, cannot prove it improved, and drifts without a frame.

## 1 · The aha

Five pieces, five lacks: MCP gives hands, RAG gives a library, memory gives a past, evals give a score, and the harness gives a frame. You can point at a failure and name the piece that was missing.

## 2 · What it denotes

Strip the names and you have five relations. MCP is a protocol by which a running agent discovers and calls services. RAG is search over a store you own, answered with the passages and their sources instead of an opinion. Memory is what survives one exchange: rows pulled out of it, plus the worker that pulls them. Evals are suites of questions with a required score and a written record of every run. The harness is everything around the model that shapes its behavior without being part of it.

In Haskell they are not one abstraction; they are one architecture. Only two of the five are code you own end to end — the other three are contracts, which is why they rot quietly.

## 3 · In your languages

Kotlin: each piece is a module with a pure core and an effect edge — the fusion rule and the corpus filter are pure, the HTTP route and the SQL are the edge. That split is what makes each piece testable without a network.

Nushell: each piece is reachable as a call from outside — `http post http://127.0.0.1:8765/rag/query` for search, `agent-brain memory recent` for the past, a script for the frame.

The difference: Kotlin builds the piece, Nushell inspects it. The snag: calling the five a stack suggests they are one program. They are five contracts, and each fails in its own way.

## 4 · In your system

| piece | one line | where it lives |
|---|---|---|
| MCP | the door that hands the brain's services to an agent as tools | `agent-brain/docs/mcp.md` |
| RAG | search over the store, answered with passages and sources | `agent-brain/core/src/main/kotlin/dev/lattenero/brain/rag/RagService.kt` |
| memory | rows pulled out of finished exchanges, and the worker that pulls them | `agent-brain/core/src/main/kotlin/dev/lattenero/brain/memory/MemoryWorker.kt` |
| evals | suites with a pass mark, and a row per run | `agent-brain/evals/suites/canon-recall.json` |
| harness | the files and hooks around the agent | `~/.zcode/AGENTS.md` |

- MCP: one implementation serves a stdio plugin and a token-gated HTTP door on 8767; it exposes six read-only tools (`rag_query`, `memory_search`, `memory_recent`, `bus_status`, `memory_status`, `eval_latest`), and no capability exists on one transport only.
- RAG: the service only looks things up — the caller composes the answer from the passages it received.
- memory: the worker pulls the finished exchanges nobody processed yet, asks a model for the durable rows, and writes them.
- evals: the suite asks forty-five concepts, twice each, and requires the right note in the top five.
- harness: the client that runs the agent is the fork, and the hooks it honors plus their trust boundary are written in `ZCode/docs/plugin-hooks-compat.md`; `~/.zcode/hooks/rag-guard.nu` queries the store before a write and injects matched law hits; `Scripts/scripts/book-check.nu` is a law written as a script that refuses a broken page.

## 6 · Drill

Read the system's own inventory, one call per piece, and see what answers.

```nu
http get http://127.0.0.1:8765/metrics | lines | length                  # RAG + memory + the wire
http get http://127.0.0.1:8765/eval/latest | length                      # evals: the table of runs
^nu /Users/lattenero/Scripts/scripts/book-check.nu /Users/lattenero/Projects/agent-brain/docs/book  # harness
```

Green when all three answer: the first two come from the running brain, the third from a law that reads the page. The failing case it rules out: a piece you believe is running because its file exists.
