# N08 · `wait.nu` — `wait-until`, no busy loops

**Denotes.** Bounded readiness polling — the ONE retry shape a command may use when it must block until a dependency answers, with the deadline as the load-bearing wall.

## 1 · The aha

Nushell ships no "wait until". The fleet's honest alternatives are launchd's exit-75 retry (the stack-up pattern) for boot-time work, and THIS for a command in your hands. The law: the deadline is MANDATORY (no unbounded loops — the reactive law), the probe is a predicate closure called until it answers true, and the interval is explicit — never a long blind `sleep` (the hook denies one at ten seconds).

## 2 · What it denotes

`wait-until` (deadline, probe, `--interval` — default 500ms): call the probe until it answers true, answer `false` when the budget expires — the caller decides what a timeout means. Verified: `wait-until 1sec {|| true }` answers `true` inside the budget; a probe that never turns true answers `false` at exactly the deadline, not before, not after.

## 3 · In your languages

**Nushell.** This module — one verb, the deadline first in the signature so it cannot be forgotten.

**Kotlin.** kap's `Schedule` is the typed ladder of the same idea (retry with schedules, `withMaxDuration`, `debounce`): the budget is a VALUE there, a named duration here. Both languages refuse the unbounded loop; the difference is that kap composes schedules and the shell composes deadlines.
