# F2 · The traps of the month

**Denotes.** A trap is a measured surprise that cost a failed run: it is written where the next writer will find it, tagged with the version that verified it, and re-read monthly so the same failure never buys the same lesson twice.

## 1 · The aha

Experience you do not record is experience you re-buy. The fleet's traps live as notes — one per campaign, every line a real failure from that night — and the method is the point: surprise → failed run → fix → note tagged `[verified <version>]` → the next writer's first read.

## 2 · What it denotes

The corpus: `nushell-kb/notes/nu-traps-2026-11-21.md`, `nu-traps-2026-11-24.md`, `nu-traps-2026-11-26.md`, `nu-traps-2026-11-27.md` — one per campaign, each line a measured failure with its fix. The tool mechanics live in one place: `nushell-kb/notes/bash-tool-laws.md` (the two mechanics, the habit translations, the silent traps, the static oracle).

The monthly read is the habit: before a new campaign in a language, read that language's traps note first — the surprises were already bought. A new trap enters the note the day it costs a run, not at month's end; the tag records which nu version verified it, so a version bump re-opens the question honestly.

## 3 · In your languages
