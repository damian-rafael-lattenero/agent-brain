# B04 · Currying and partial application

**Denotes.** A multi-argument function read as a chain of single-argument functions — so fixing the first argument answers a function of the rest. Partial application is that fix, held for later.

## 1 · The aha

`rate(currency, cents)` forces both answers at once. `rate currency = \cents -> ...` gives the currency now and the cents later — the function you hand to a pipeline today, finished by the data that arrives tomorrow.

## 2 · What it denotes

In Haskell every function takes ONE argument: `f :: a -> b -> c` IS `a -> (b -> c)`. Partial application is not a feature — it is what evaluation already does. Sections (`(0-)`), operator fixes and point-free definitions are all this one fact wearing different hats.

## 3 · In your languages

**Kotlin.** No auto-currying: a parameter list is a tuple. The curried form is written on purpose — `fun rate(currency: String): (Int) -> String` — and earns its keep only where partial reuse exists (the anti-dogma law: two call sites stay explicit). Full row: `kotlin-kb/notes/canon-map.md`, `currying`.

**Nushell.** Same tuple truth: the partial application is a closure over the rest, called with `do`. The sharp edge: the closure captures its value at creation — a partial application over a changing slot keeps the old value forever. Full row: `nushell-kb/notes/canon-map.md`.
