# B23 · Free monad and tagless final

**Denotes.** A program kept as a pure description — a tree of instructions, or operations behind an interface — whose meaning a later interpreter gives it.

## 1 · The aha

The free monad does not run the program; it holds it. `puts s = liftF $ Puts s ()` builds a VALUE; nothing reaches the terminal until `interp` walks the tree. Reading the word monad as effect is the mistake: what is built is a "pure description of the computation" (wiwinwlh), and the effect belongs to the interpreter.

## 2 · What it denotes

In Haskell: `data Free f a = Pure a | Free (f (Free f a))` — the monad over any functor, `iter :: Functor f => (f a -> a) -> Free f a -> a` the interpreter-fold. Its three monad laws are green in the law suite over a toy instruction functor. Tagless final answers from the other side: terms are "functions bound to typeclasses rather than data constructors" (wiwinwlh) — extend the language without changing the base.

## 3 · In your languages

**Kotlin.** No HKT (B18), so no true `Free f` — the sealed instruction tree + fold IS the free shape, and the operations interface IS tagless final. Verified: one script, two interpreters (`[hi, bye]` and `[HI][BYE]`). Full row: `kotlin-kb/notes/canon-map.md`, `free-monad-tagless-final`.

**Nushell.** The program as a list of inert instruction records; the interpreter is `each`/`reduce` over it; the pitfall is the closure payload that RUNS while being built — the payload stays inert. Full row: `nushell-kb/notes/canon-map.md`.
