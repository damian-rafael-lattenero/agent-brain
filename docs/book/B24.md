# B24 · Streaming and backpressure

**Denotes.** Processing a sequence in bounded memory by consuming each element as it is produced — a slow consumer holds the producer back instead of data piling up.

## 1 · The aha

Prelude input manifests everything in memory before any work starts; lazy IO (B16's islands) ties effect order to evaluation order — "difficult to reason about in the large" (wiwinwlh). The fix is a PROTOCOL: `await`/`yield` verbs plus a composition operator, so memory stays constant and cleanup stays deterministic.

## 2 · What it denotes

In Haskell: pipes' `await :: Pipe a y m a`, `yield`, `(>->)`, `runEffect` — and conduit's twin, where `await` answers `Maybe i` (no-more-input is a value). The composition laws of `(>->)` make `cat` the identity and composition associative (bibliography: Gonzalez, *Pipes*).

## 3 · In your languages

**Kotlin.** kap-stream names the policy as a VALUE at every stage: the `Backpressure` ADT — Suspend · Buffer(n) · Conflate · DropOldest(n) · DropLatest(n). The laws: exact strategies never drop; lossy strategies drop only what they name; survivors keep upstream order (verified: cap 2 fed `1,2,3` → DropOldest `[2,3]`, DropLatest `[1,2]`). Full row: `kotlin-kb/notes/canon-map.md`, `streaming-backpressure`.

**Nushell.** No named-strategy channel — the discipline is the reactive law: bounded fan-out (`traverse-jobs --timeout`), mandatory deadlines (`wait-until`), `job recv --timeout` raising as the honest failure signal. Full row: `nushell-kb/notes/canon-map.md`.
