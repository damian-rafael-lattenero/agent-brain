# C3 · A turn becomes memory: the extraction worker

**Denotes.** One completed turn becomes rows you can search later: one model call reads the turn's organized transcript and returns typed records — facts, decisions, preferences, one summary — under a parse that can only answer parsed or invalid.

## 1 · The aha

The bus records the turn; recording is not knowing. The worker takes each unprocessed completed turn, renders it as one bounded text — prompt, reply, which calls ran — and asks the model once: what here is worth keeping? The answer is a typed value or nothing usable; garbage never becomes a memory by accident.

## 2 · What it denotes

`Transcript` — `(eventId, sessionId, turnId, prompt, reply, tools, title)` — to `MemoryExtractor.extract` → `Extraction` (facts, decisions, preferences, summary). The parse is a sum: `ParseOutcome.Parsed` or `ParseOutcome.Invalid` with the reason and the raw text — a total, exception-free classification, with the caps enforced in the validator (item length, items per kind, summary length) and pinned by property laws.

The invalid answer is not silence: the raw text travels with the reason into the invalid bin, so a broken model answer is a finding, never a dropped turn. The model call rides the same resilience family as every other model call — timeout converted, retried with jittered backoff, a circuit breaker — and the worker drains unprocessed completions in bounded batches, settled one by one: one failed extraction never stops the queue.

## 3 · In your languages

Kotlin: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/memory/MemoryExtractor.kt` holds the prompt, the schema, the bins and the caps together; `agent-brain/core/src/main/kotlin/dev/lattenero/brain/memory/MemoryWorker.kt` is the kap process — schedule, restart policy, meters — that drains the queue.

Nushell: the same rows read after the fact — the store's counts by kind, folded from Postgres, tell you what the worker has been turning out.

The difference: Kotlin extracts, Nushell counts. The snag: a schema-valid but empty answer is still a valid parse — the caps and the blank checks are what keep emptiness from becoming rows.

## 4 · In your system

1. The queue: completed turns without a memory row, drained in bounded batches — `agent-brain/core/src/main/kotlin/dev/lattenero/brain/memory/MemoryWorker.kt`.
2. The one call: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/memory/MemoryExtractor.kt`, temperature 0, the schema forced by the wired providers.
3. The bins: `Parsed` lands as rows (fact · decision · preference · summary); `Invalid` goes to the invalid bin with the raw text and the reason.
4. The rows: `agent-brain/core/src/main/sqldelight/dev/lattenero/brain/db/sq/Memories.sq` — keyed by `source_event_id`, so a replayed turn extracts once.
5. The report: scanned, extracted, invalid — every pass speaks its own counts.

## 6 · Drill

Count what the worker has been turning out:

```nu
^docker exec agent-brain-pg psql -U brain -d agent_brain -At -c
"select kind, count(*) from memories group by kind order by 2 desc"
```

Green when the four kinds answer with plausible counts and no kind is silently zero. The failing case it rules out: an extractor that pretends — if the worker ran and the counts did not move, the counts are the witness, not the log line.
