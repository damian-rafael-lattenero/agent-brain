# B16 · Laziness

**Denotes.** A binding as a promise: the work happens when the value is first needed, not when the line runs — and the direction of a fold can end a walk before its input ends.

## 1 · The aha

Strictness pays for everything eagerly, including answers nobody reads. Laziness turns the bill into pay-per-read — and its shadow side is the guard that never runs because its value was never touched (the U8 silent-skip bug's cousin, on the value side).

## 2 · What it denotes

In Haskell EVERY binding is a promise: `foldr` consumes one constructor at a time, so it can end early on a list that never ends, and `undefined` at position 400 is harmless if the answer stops at 3. The law run `Laziness.hs` pins it executably (`Laziness.hs`): the early-ending fold over an infinite structure.

## 3 · In your languages

**Kotlin.** Strict everywhere, three islands: `lazy {}`, `by lazy`, and `sequence {}`/`asSequence()` — the unbounded generator that terminates under `take`. The deferred side effect is the pitfall: a `lazy { publish() }` never read is a publish that never happens. Full row: `kotlin-kb/notes/canon-map.md`, `laziness`.

**Nushell.** The island is the CLOSURE: a thunk built but not called until `do` touches it (`nushell-fp/mods/lazy.nu` carries the sanctioned pattern). The forgotten `do` is the same pitfall. Full row: `nushell-kb/notes/canon-map.md`.
