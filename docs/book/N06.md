# N06 · `json.nu` — `get-in`/`set-in`/`deep-merge-all`

**Denotes.** Readers and writers over structured records — reading, writing and merging deep paths safely, the JSON-shaped day-to-day of config and wire data.

## 1 · The aha

Gaps ONLY: nushell 0.117 already ships the heavy machinery — `merge deep` IS deep-merge, `get -o` and `upsert` cover LITERAL cell paths. What the builtins miss is the DYNAMIC path (a path computed at runtime, held as a list) and the honest default when a branch is missing. That gap is the module.

## 2 · What it denotes

`get-in` (a deep read with a default: `[http host]` on a record with no `host` answers the default, never a crash), `set-in` / `update-in` (deep writes through dynamic paths), `deep-merge-all` (many records into one, right-wins on leaves), `flatten-keys` / `unflatten-keys` (the dot-path round trip). Verified: `get-in [http host] 'unset'` on `{http: {port: 8080}}` answers `unset` — a missing branch yields the default instead of crashing mid-pipeline.

## 3 · In your languages

**Nushell.** This module — dynamic paths as values, the default carried by the reader.

**Kotlin.** The same idea lives in the bot's wire records and kap's `get-in`-style safe accessors: parse the JSON ONCE at the boundary into typed records (parse-don't-validate), and a missing field becomes a typed absence instead of a probe. The shell version is for the untyped middle: configs, health JSON, API payloads a script reads once.
