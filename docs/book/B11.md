# B11 · Functor

**Denotes.** A context you can map over — the same shape, every element transformed, and two equations (identity, composition) that make "shape-preserving" provable rather than decorative.

## 1 · The aha

Without the laws, every `map`-shaped function is trusted by hope: one that silently filters or drops inside answers a DIFFERENT shape, and nothing tells you. Identity and composition are the two tests that turn "map" into a promise.

## 2 · What it denotes

In Haskell: `class Functor f where fmap :: (a -> b) -> f a -> f b` with the laws `fmap id == id` and `fmap (g . f) == fmap g . fmap f` — pinned by the executable law run `Functor.hs`. The abstraction is ONE function working over EVERY shape with an instance.

## 3 · In your languages

**Kotlin.** `map` per shape — collections, `Box<T>`, Arrow's `Either` — each by its own signature; the laws are TESTS, not instances (kap's LAWS.md carries the executable Functor laws: `fa.map { it } == fa`). The shape-changing map is the caught bug: identity fails on anything that drops. Full row: `kotlin-kb/notes/canon-map.md`, `functor`.

**Nushell.** `option-map` in `nushell-fp/mods/types.nu` — law tests in-file, mirroring kap; `each` over lists is the everyday map, and the same promise applies: same length, same order, transformed elements. Full row: `nushell-kb/notes/canon-map.md`.
