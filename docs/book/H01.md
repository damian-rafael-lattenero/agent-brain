# H01 · Category: composition that behaves

**Denotes.** Objects and arrows in which every composable pair has exactly one composite, composition is associative, and every object carries an identity arrow — nothing more, and nothing less.

## 1 · The aha

Composition that always works, and always behaves, is the entire definition: what an object *is* plays no part. You already live in one — the nu pipeline and the Kotlin call chain are arrows glued by an operator that must never surprise you.

## 2 · What it denotes

The shape: `f : A → B` and `g : B → C` give `g ∘ f : A → C`; `h ∘ (g ∘ f) = (h ∘ g) ∘ f`; and one `id_A : A → A` per object with `f ∘ id_A = f` and `id_B ∘ f = f`. In Haskell the objects are types, the arrows are functions, and the two laws are the same two: `id` is the identity of `(.)`, and `(.)` is associative — `haskell-kb/notes/concepts/composition.md` carries the executable side.

The encoding only approximates the mathematics: the `Category` class in `Control.Category` cannot represent anything wider than the category of types, functions that may return bottom are partial and so are not arrows, and the laws are unchecked — equality is not defined for functions. Full theory: `theory-kb/notes/category-theory/category.md`.

## 3 · In your languages

**Kotlin.** Composition is by chaining — the scope functions `let`, `run`, `with`, `apply`, `also` glue steps, and the docs warn to "be careful when chaining them": the chain is an arrow, and nothing in the compiler checks the two laws for you. kap carries composition as a law instead. Full row: `kotlin-kb/notes/canon-map.md`, `composition`.

**Nushell.** The pipeline IS the category shape: "a pipeline is composed of three parts: the input, the filter, and the output", and a custom command declares its arrow with a signature — `def "str stats" []: string -> record { ... }`. The parser type-checks each arrow's ends; associativity is the reason a long pipeline reads the same grouped any way. Full row: `nushell-kb/notes/canon-map.md`, `composition`.
