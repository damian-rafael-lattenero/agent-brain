# A0.3 · Index, queue, latency

**Denotes.** Slow work is made fast by three moves: an index turns looking into jumping, a queue turns waiting into a line, and latency is the price of one answer measured instead of guessed.

## 1 · The aha

An index spends work once so that later calls do not pay it again. A queue holds work outside the caller's clock. Latency is what the caller feels while the first two do their job.

## 2 · What it denotes

An index is a second copy of the data arranged for one question: a lookup from content to place. A queue is a buffer plus an order — work waits somewhere else until a worker drains it. Latency is one answer's elapsed time; throughput is answers per unit of time; a cache is an index over finished results, keyed by the input.

In Haskell an index is a `Map` built by a fold, a queue is a list of pending values a worker consumes, and latency is a monotonic duration. All three exist for the same reason: to keep one call from doing unbounded work.

## 3 · In your languages

Kotlin: the index is a table in Postgres, filled by a pass that compares a content hash and skips a document whose text did not change — the cache is that one comparison. The same code writes the elapsed milliseconds of every query next to the answer it served.

Nushell: the queue is a job, `job spawn` with a mailbox (`Scripts/nushell-fp/mods/async.nu`), and `wait-until` (`Scripts/nushell-fp/mods/wait.nu`) is how a script waits for a condition without a busy loop.

The difference: Kotlin's queue survives a restart because it is a table; a Nushell job dies with its shell, so anything durable must live outside it. The snag: a poll interval is not a measure of speed, it is the floor under the latency nobody measured.

## 4 · In your system

📍 The index is two tables, documents and chunks, declared in `agent-brain/core/src/main/sqldelight/dev/lattenero/brain/db/sq/Rag.sq`, and the pass that fills them is `agent-brain/core/src/main/kotlin/dev/lattenero/brain/rag/Indexer.kt`.

The queue is a table with a timestamp: `agent-brain/core/src/main/sqldelight/dev/lattenero/brain/db/sq/BusEvents.sq` selects pending work where the processing mark is still empty, and the worker polls it every 2000 ms, the value of `memory_poll_ms` in `agent-brain/core/src/main/kotlin/dev/lattenero/brain/config/Config.kt`.

Latency is measured, not assumed: every query stores its own `latency_ms` in `agent-brain/core/src/main/sqldelight/dev/lattenero/brain/db/sq/RagQueryLog.sq`, written from the elapsed mark in the route that served it.

## 6 · Drill

Run one query, then read the number the brain recorded for it.

```nu
let t = (timeit { http post http://127.0.0.1:8765/rag/query {query: "partial application", k: 3} });
^psql postgresql://brain:brain@127.0.0.1:5433/agent_brain -Atc 'select latency_ms from rag_query_log order by id desc limit 1';
$t
```

Green when the stored `latency_ms` is the same order as the wall time you just measured. The failing case it rules out: no row at all, which means the logger is off and the number you would quote is a guess.
