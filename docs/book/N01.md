# N01 · `types.nu` — Option and Result as values

**Denotes.** The two ADTs nushell lacks, encoded as tagged records — absence and failure become values every pipeline can carry, match and compose.

## 1 · The aha

Nushell has no sum types, so `null` and thrown errors used to be the only answers. The encoding is the classic one: a record with a `tag` discriminator and a uniform shape — `{tag: "some", value: a}` / `{tag: "none", value: null}` for Option, `ok` / `err` for Result — where both constructors fill EVERY field (null where absent), so signatures stay exact.

## 2 · What it denotes

One battery of combinators over the two shapes, each the Haskell verb under its nushell name: `option-map`/`option-bind` (fmap/`>>=`), `option-ap` (`<*>`, the four applicative laws test-pinned), `option-match` (the eliminator), `traverse-option` (first none collapses), and on the Result side `attempt` (the bridge from the impure world: run an unsafe closure, get a value), `fold-result` (foldM: first err stops), `result-ap`, `traverse-validated`. Verified: `attempt {|| 2 + 3 }` answers `{tag: ok, value: 5}`; `traverse-validated` over two failures answers `error: [a, b]`.

## 3 · In your languages

**Nushell.** This module IS the answer — no sum types, so the tagged-record encoding plus the laws pinned in `test_types.nu`, mirroring kap's LAWS.md.

**Kotlin.** kap's `Either` and `Validated` carry the same design, and the citable ruling rides both languages: `traverse-validated` ACCUMULATES every error (applicative, deliberately not a monad — B25's decision), while short-circuiting lives in `traverse-option`/`fold-result` and kap's `Either.andThen`.
