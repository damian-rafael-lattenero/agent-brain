# A0.2 · JSON, schema, types

**Denotes.** JSON is the plain shape data takes on the wire, a schema is the written promise about that shape, and a type is the same promise the language can check before anything runs.

## 1 · The aha

Data on the wire is only text. Three things make it usable: a common shape (JSON), a written promise about that shape (a schema), and a checker that runs either before the program (a type) or at the door (a parse).

## 2 · What it denotes

JSON gives six forms: object, array, string, number, boolean and null. That is all it has. A schema says which of those forms may appear where and which fields are required; a type is the same description written so the language can refuse a program that breaks it.

In Haskell the difference is plain: `Aeson.Value` is anything JSON allows, while a decoded record with named fields is what you are allowed to use. The gap between the two is the whole art — decode once at the edge, then never look at `Value` again.

## 3 · In your languages

Kotlin puts the schema in the type: `@Serializable data class QueryRequest(val query: String, val k: Int = 5)` both describes the shape and generates the parser, so a missing `query` never reaches your code as a null.

Nushell keeps the value open: `open config.json | from json` gives a record, `describe` tells you its shape at runtime, and `get -o` follows a key that may be absent.

The difference: Kotlin fails to build, Nushell fails to evaluate. The snag: `get -o` cannot tell a missing key from a key whose value is null — both come back as nothing, so a rule that distinguishes them needs an explicit check.

## 4 · In your system

📍 The brain refuses a config file with a key it does not know. `agent-brain/core/src/main/kotlin/dev/lattenero/brain/config/Config.kt` throws `ConfigException` naming the unknown keys, because a typo must not degrade into a silent default.

The HTTP edge keeps the same law: a body of the wrong shape gets a 400 that names the expected fields, through `agent-brain/core/src/main/kotlin/dev/lattenero/brain/http/Server.kt`.

On the line-based wire, each record is decoded into a typed value at the edge: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/bus/BusEvent.kt` turns a bad line into a reported value instead of a crash, and refuses a kind outside its list.

## 5 · Paper sheet

```
signature:  decode(schema, text) -> Result<Value, Error>
law:        parse after serialize is the identity, on the values the schema admits and no others
drawing:    text --parse--> value --validate(schema)--> typed record --serialize--> text
own_words:
```

## 6 · Drill

Send a body without the required field and read the refusal; then send the right one.

```nu
http post --full http://127.0.0.1:8765/rag/query {k: 5} | get status                          # 400: the schema says no
http post --full http://127.0.0.1:8765/rag/query {query: "partial application", k: 1} | get status  # 200
```

Green when the first prints `400` and the second prints `200`. If the first prints `500`, the door is checking too late: the schema belongs at the edge, where the text enters.

## 8 · Close-out

- Denotes: text with a shape, a promise about the shape, and a checker for the promise.
- Lives: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/config/Config.kt`, `agent-brain/core/src/main/kotlin/dev/lattenero/brain/http/Server.kt`, `agent-brain/core/src/main/kotlin/dev/lattenero/brain/bus/BusEvent.kt`.
- Now you can read any decoder at the edge and say which law it keeps and which it drops.

Checkpoint: `http post --full http://127.0.0.1:8765/rag/query {k: 5} | get status` prints `400`.

## Minimum path

- **The aha**: JSON is one shape for text, a schema is the promise, a type is the promise the language can check.
- **The signature**: `decode(schema, text) -> Result<Value, Error>`.
- **The checkpoint**: the call without `query` prints `400`; the call with it prints `200`.
