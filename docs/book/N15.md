# N15 · `telegram.nu` — the phone as an output

**Denotes.** The deploy announce rung: one function every repo's deploy script shares, silent by design — a deploy never dies because the phone is off.

## 1 · The aha

The SAME announce function lived copy-pasted in three repos (the bot, whatsdigest, the fork's fork-ops) until the audit wave deduplicated it into the library. The design decision that matters is the silence: a missing config, an empty token or chat, a dead network — ALL no-ops. The deploy's own gate decides whether the deploy proceeds; the phone is an output, never a dependency.

## 2 · What it denotes

`send-telegram` (text, `--html`): read the config, send through the Bot API, and on ANY absence or failure stay silent and succeed. Verified: with no config in the environment the call is a silent no-op — the deploy reports, the phone just does not ring. The verb is one rung in the notification ladder; the owner-facing voices (the seal, the digest) live in the bot, not here.
