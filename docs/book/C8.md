# C8 · MCP: what it is and what the brain exposes

**Denotes.** The Model Context Protocol is a standard way for AI agents and LLM-based software to reach programs on your machine — and the brain exposes its four read-only doors through it.

## 1 · The aha

One protocol, any client. The same four doors answer the desktop session, the phone bot, and any other MCP-speaking program — because the doors are the SERVER's vocabulary, not the client's: tools with declared inputs, resources with declared shapes.

## 2 · What it denotes

MCP is client-server: a host session speaks the protocol, a server exposes named capabilities. Nushell ships one built in — "The Model Context Protocol (MCP) is a standard way for AI agents and other LLM-based tools to call tools that run on your machine. Nushell has a built-in MCP server." The brain's side: four read-only tools (`rag_query`, `memory_search`, `memory_recent`, `bus_status`) plus its HTTP doors — the plugin is a facade over the same API, loopback with a bearer, fail-closed (the V10 red-team drill: 10 PASS, 0 FAIL).

Read-only on purpose: the brain serves, the caller decides. Generation never happens inside the brain — C6's journey ends at ranked passages with their sources.

## 3 · In your languages

**Kotlin.** The bot talks HTTP, not MCP: `BrainGateway` carries the doors as suspend lambdas, one per route, each degrading alone (down, timeout, HTTP error, unreadable, empty). Full row: `kotlin-kb/notes/canon-map.md`, `composition`.

**Nushell.** From a script, the same doors are plain calls: `http get http://127.0.0.1:8765/health` answers the config snapshot, no SDK involved. Full row: `nushell-kb/notes/canon-map.md`, `composition`.
