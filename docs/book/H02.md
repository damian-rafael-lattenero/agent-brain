# H02 · Functor: the same operation on another container

**Denotes.** A map between two categories that sends objects to objects and arrows to arrows without tearing — composition and identities survive the trip.

## 1 · The aha

B11 taught the endofunctor you program with: one shape, `fmap`, two laws. The general notion is the same promise one level up: a whole mapping of categories, and "a functor is not allowed to introduce any tears into this fabric" — it may smash and glue, never break apart.

## 2 · What it denotes

`F : C → D` acts on objects and on arrows: `f : a → b` gives `F f : F a → F b`, with `F (g ∘ f) = F g ∘ F f` and `F id_a = id_{F a}`.

In Haskell, `class Functor f where fmap :: (a -> b) -> f a -> f b` — an instance is an endofunctor on the category of types and nothing wider, the kind of `f` must be `* -> *`, and the laws are unchecked: "the only requirement to be a `Functor` is an implementation of `fmap` with the proper type".

The reader instance shows `fmap` is not looping: `fmap f g = f . g`. Full theory: `theory-kb/notes/category-theory/functor.md`.

## 3 · In your languages

**Kotlin.** `Flow.map`: intermediate operators "consume values from the flow, apply an operation to them, and return another flow" — one operator, every value, shape preserved. The smallest law breaker still compiles: a `map` that drops elements passes every type check and fails `fmap id = id` only under test. Full row: `kotlin-kb/notes/canon-map.md`, `functor`.

**Nushell.** `each` — "run a closure on each row of the input list, creating a new list with the results" — is the everyday map, with the same promise: same length, same order, transformed elements; `par-each` does it in parallel and warns "the list will become arbitrarily disordered". The type signatures have no generic parameter: `each` is written per concrete input, the language's honest ceiling. `option-map` in `nushell-fp/mods/types.nu` carries the laws in-file. Full row: `nushell-kb/notes/canon-map.md`, `functor`.
