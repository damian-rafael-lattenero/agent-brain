# B01 · Pure functions

**Denotes.** A pure function touches nothing but its parameters and returns everything it made — the same arguments answer the same value, always, no matter when or who calls. The ground every later card stands on.

## 1 · The aha

A function that also reads the clock or a global is two functions in one: the one you named, and the one the state wrote. The pure function has no second author — what you see in the signature is the whole story.

## 2 · What it denotes

In Haskell the signature cannot lie: a function whose type says `Int -> Int` gets the world nowhere — no reading, no writing, no time. Referential transparency is the promise that an expression can be replaced by its value, which is why the checker, the tests and the reader all trust the same thing.

## 3 · In your languages

**Kotlin.** No effect system, so the law is positional: computation functions stay pure by inspection; the functions that touch the world are `suspend`, live at the edges, and say so by name. A hidden read (a companion-object field, a global) is the disqualifier — the answer depends on state the signature never mentions. Full row: `kotlin-kb/notes/canon-map.md`, `pure-function`.

**Nushell.** A def is pure when it touches nothing but its parameters: no `$env` writes, no file reads, no slots outside its own scope. The house layout enforces it structurally — pure cores inside the mods folder, effects at the scripts that call them. Full row: `nushell-kb/notes/canon-map.md`.
