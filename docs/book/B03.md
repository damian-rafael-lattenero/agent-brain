# B03 · First-class and higher-order functions

**Denotes.** A function is a value like any other — passed, returned, stored in a list or a table row — and a higher-order function is one whose parameter or answer is such a value. The mechanics behind every pipeline and dispatch table in the fleet.

## 1 · The aha

Once a function is a value, the loop that applies steps never learns their names: the steps travel as data, the fold carries them, and adding a step is adding a row — no caller changes.

## 2 · What it denotes

In Haskell this is not a feature but a fact: `(a -> b)` is a type like `Int`, and `map`, `filter` and `foldr` are ordinary functions that take one. The capability is what makes the algebra above it expressible — the structure-preserving map takes a function and answers one.

## 3 · In your languages

**Kotlin.** Function types (`(A) -> B`), references (`::trim`) and lambdas are the story; `suspend (A) -> B` is a DIFFERENT type — the mismatch is the sharp edge, and wrapping one to fit is the smell. Full row: `kotlin-kb/notes/canon-map.md`, `first-class-functions`.

**Nushell.** Closures are the values: dispatch tables carry them as payload fields (a thunk built at construction, called only by the winning row — the eager-payload rule from the defer law), `each`/`where`/`reduce` take them, and `do` calls one. A closure captures its environment by VALUE at creation. Full row: `nushell-kb/notes/canon-map.md`.
