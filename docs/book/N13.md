# N13 · `prop.nu` — properties over examples

**Denotes.** The property-based-testing harness: a law as a Bool-valued function over GENERATED cases, seeded for replay, shrinking when it fails — B22's nushell home.

## 1 · The aha

The PBT recipe made mechanical: state the INVARIANT as a closure over a generated sample, define the input space with generators biased to the edges (empty and singleton lists occur by construction), make failure REPLAYABLE, and shrink the counterexample. The measured constraint that shaped everything: nushell's `random` is NOT seedable (verified 0.117 — no `random seed` subcommand), so the generators are PURE functions of an explicit int seed — splitmix-flavored mixing — and every run derives its seed from the root.

## 2 · What it denotes

`gen-int` / `gen-list-int` (the seeded generators), `for-all` (the runner: N cases, a verdict record — `tag: ok` with the runs and seed, or `tag: err` with the failing index, ITS seed and the sample), `shrink-list` (shrink-lite: empty, halves, tail — the first still-failing candidate wins, because a counterexample reported as `[]` is the clearest message and one reported as 12 noisy ints is not). Verified: the monoid identity over 10 seeded runs answers `{tag: ok, runs: 10, seed: 7}`.

## 3 · In your languages

**Nushell.** This module — the tagged verdicts compose with `types.nu` like everything else.

**Kotlin.** kap-kotest's parameterised law suites (`backpressureLaws(producer, items).verify()`) are the same idea at the type level: the suite owns the generation, the implementation supplies the instance. QuickCheck's type-driven generation has no nushell equivalent — the generator IS the input space, written by hand (B22's honest gap).
