# N09 · `async.nu` — jobs, mailboxes, structured concurrency

**Denotes.** The applicative functor over nushell's background jobs — independent work spawned as threads, structure restored from the mailbox as results land.

## 1 · The aha

kap's `.with` applies a deferred computation to a curried function and the graph runs them concurrently. The nushell twin: a background `job spawn` is the deferred value; it sends its result to the main mailbox (`job send 0`) carrying its position; the main thread blocks in `job recv` (zero polling) and order is restored by sorting on the index. `--timeout` is the failure signal: on expiry every spawned job is killed and the error is honest.

## 2 · What it denotes

`traverse-jobs` (a list of closures IN, their results in structure order OUT — out-of-order arrival re-sorted by index), `build-record-jobs` (the record fields as independent jobs — `build-record-par`'s engine), `apply-async` (apply a deferred value to a curried function). Calls are isolated by a per-call random tag: a killed job's dying catch can still deliver its outcome, and the tag keeps that stale message away from every later call (the mailbox isolation law). Verified: three closures through `traverse-jobs` answer `[1, 2, 3]`.

## 3 · In your languages

**Nushell.** This module — jobs are THREADS: they die when the process exits, so this is in-process async only; anything that must survive goes to a LaunchAgent or a Ghostty tab.

**Kotlin.** Coroutines with structured concurrency: the scope owns its children exactly as the mailbox owns its jobs; cancellation propagates the same way. kap's applicative parallelism (`.with`, `traverseSettled`) is the same shape with typed errors. The isolation law (a child's failure is an ordinary failure; the operator is NOT cancelled) is shared.
