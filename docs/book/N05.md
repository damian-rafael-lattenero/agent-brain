# N05 · `list.nu` — lists as the default shape

**Denotes.** The list combinators nushell's builtins leave as gaps — the second half of a fold, the disjoint split, the running total, the anamorphism.

## 1 · The aha

The gap-check law names nushell's builtins first (`each`, `where`, `reduce`, `zip`, `chunks`, `uniq`, `flatten`, `transpose`, `interleave`), and THIS module is what "then check the library" means: fifteen functions for the shapes builtins genuinely lack. Nothing here re-wraps a builtin — the gaps-only law in list form.

## 2 · What it denotes

The workhorses: `span` (split at the first predicate failure — taken and rest), `partition` (the disjoint split, one pass), `scanl` (the inclusive prefix fold nushell lacks — running totals), `unfold` (the anamorphism: a step returns `{emit, next}` or null), `zip-with`, `cartesian`, `powerset`, `unzip`, `map-fst`/`map-snd`. And the applicative family for lists: `ap-list` (`<*>`: every closure over every value), `lift-a2`, `filter-m`, `replicate-m`. Verified: `[1 2 3 4] | scanl (+) 0` answers `[0, 1, 3, 6, 10]`.

## 3 · In your languages

**Nushell.** This module — the fifteen gaps, each with its test in `test_list.nu`.

**Kotlin.** The stdlib already carries every one (`takeWhile`/`span`, `partition`, `runningFold`, `generateSequence`); Kotlin needs no gap library for lists. The asymmetry IS the lesson: the shell's fold vocabulary is younger, and the library is where the missing verbs live while the language grows.
