# B14 · Semigroup and Monoid

**Denotes.** A way of combining values where grouping does not matter, plus one value that changes nothing — named once, so one fold serves every case.

## 1 · The aha

Summing prices, concatenating logs, AND-ing flags: three folds that differ only in what combines and what the empty value is. A monoid names those two things once — `foldMap g = mconcat . map g` then works for any combine (the Typeclassopedia'"'"'s general fold).

## 2 · What it denotes

In Haskell: `class Semigroup a` with `(<>) :: a -> a -> a`; `class Monoid a` adds `mempty :: a`. The laws: left identity `mempty <> x = x`, right identity `x <> mempty = x`, and associativity — the ONLY law of Semigroup. `Sum` and `Product` are wrapper types (B17) that give numbers their two monoids.

## 3 · In your languages

**Kotlin.** No typeclasses — the interface encoding: `Monoid<A>` with `empty` + `combine`, one fold (`xs.fold(m.empty) { acc, x -> m.combine(acc, f(x)) }`). Verified: `foldMap(1..5, SumInt) = 15`; kap has no Monoid — do-not-reinvent: a plain fold when one combine suffices. Full row: `kotlin-kb/notes/canon-map.md`, `semigroup-monoid`.

**Nushell.** The dictionary record `{empty, combine}` (algebra.nu), with ready-made `monoid-sum`/`monoid-str`/`monoid-all`; `reduce` without `--fold` is the half-monoid that raises on empty. Full row: `nushell-kb/notes/canon-map.md`.
