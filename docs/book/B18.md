# B18 · Higher-kinded types

**Denotes.** Abstracting over a TYPE CONSTRUCTOR — `Functor f` speaks about every shape with an instance — the abstraction level that turns per-shape code into one generic definition.

## 1 · The aha

Without it, `map` is written per shape forever: list-map, box-map, opt-map. With it, `fmap` is written ONCE and each shape supplies an instance — the step from "functions that work on shapes" to "laws that work on every shape".

## 2 · What it denotes

In Haskell: `f` in `Functor f` is a type CONSTRUCTOR (a shape), not a type — the kind `* -> *`. One `fmap`, instances per shape, and generic functions (`doubled = fmap (* 2)`) that work on anything with an instance, including shapes written years later.

## 3 · In your languages

**Kotlin.** No HKT — the JVM's ceiling. The workaround is the instance-passing pattern: the "class" is an object per shape, passed explicitly (B10's pattern at the constructor level). kap chose concrete operators per shape over a generic framework — the honest ceiling answer. Full row: `kotlin-kb/notes/canon-map.md`, `higher-kinded-types`.

**Nushell.** Total absence — no generics beyond `list<T>`; the per-shape operator table plays the role, and the shape never becomes a parameter (the stringly-typed shape dispatch is the pitfall). Full row: `nushell-kb/notes/canon-map.md`.
