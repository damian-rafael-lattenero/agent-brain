# N14 · `highlight.nu` — the syntax highlighter

**Denotes.** Terminal highlighting routed by language — `nu-highlight` for nushell, `bat` for everything else — plus the display ADT that pretty-prints structured strings from the inside.

## 1 · The aha

Two gaps, one module: `nu-highlight` is nushell's only highlighter and it speaks only Nushell; `bat` ships no Nushell grammar. So the router sends `.nu` to `nu-highlight` (the active `$env.config.color_config` palette) and every other language to `bat --theme=ansi` (the terminal palette, not a bundled theme). The deeper half: serializers escape strings by design, and neither highlighter looks INSIDE a string value — so the module walks the tree and expands each structured leaf: embedded JSON pretty-printed, multi-line text as real lines, Nu code highlighted.

## 2 · What it denotes

The routing: `highlight-language` (explicit override, else the extension, else `""`), `highlight-text` (nu routes to nu-highlight, everything else to bat), `hl` (files or piped input). The ADT: `structured-output-kind` (json / jsonl / csv / tsv — conservative, no prose guessing), `structured-output-text` (pretty-print JSON at two spaces), `shape-escape` (a color_config shape to SGR — `ansi` is unusable off-TTY, measured), `classify-display` (parse any value ONCE into the tagged display tree), `fold-tree` (the one recursive fold: recursion lives here, each constructor has its own closure), `render`/`out`/`render-expanded`. Verified: `'x.nu'` routes to `nu`; `'{"a": 1}'` kinds as `json`.

## 3 · In your languages

**Nushell.** This module — the router, the kind detector and the display tree.

**Kotlin.** The ZCode fork's code viewer is the twin: shiki v4 already ships the nu/kt/hs grammars and `EXTENSION_TO_LANGUAGE` maps by extension — the same routing decision, made where the renderer lives. The fork renders in the UI; the shell renders in the terminal; both refuse to guess a language the file does not name.
