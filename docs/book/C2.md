# C2 · The bus: what travels and who publishes it

**Denotes.** Every exchange between your bots and the app becomes one JSON line appended to a file — the bus records what happened, and it never commands anything.

## 1 · The aha

A call needs both sides alive at the same moment; an event does not. The bus turns each moment of a turn into a line — appended once, readable later by anyone, surviving every restart — and one bad line dies alone instead of stopping the tail.

## 2 · What it denotes

`BusEvent`: seven fields on the wire — id, ts, kind, sid, turn, source, payload. The taxonomy is a TYPE: an unknown kind fails the decode, so no downstream code ever sees an off-taxonomy event, and unknown payload fields are ignored so producers can grow without a lockstep release.

Delivery is at-least-once: the same line can arrive twice, so the row id IS the event id and the ingest inserts with `ON CONFLICT DO NOTHING` — a replay leaves the table identical. The transport is a sum (file tailer or Kafka) behind one handler; the durable rows land first, the derived projections (the cost table) after — derived data never delays the source.

## 3 · In your languages

Kotlin: the producer lives in the daemon's wiring, never in the channel — `zcode-bot-kotlin/modules/daemon/src/main/kotlin/dev/lattenero/bot/daemon/bus/BusProducer.kt` maps tap shapes to kinds: the text registers before the wire (a refused delivery is not a prompt), the stream frames carry the turn's arc, and the final reply is fetched off the read loop with a timeout.

Nushell: the same file read as data — the hub's scripts fold the lines with `from json` per line, a view after the fact, never the bus itself.

The difference: Kotlin publishes and ingests, Nushell folds after the fact. The snag: a tap's failure is swallowed into one log line on purpose — the bus never breaks a turn — which also means silence is possible, and only counting the rows exposes it.

## 4 · In your system

1. The file: `~/.zcode/agent-brain/bus-events.jsonl`, one JSON object per line, append-only.
2. The taps: `zcode-bot-kotlin/modules/daemon/src/main/kotlin/dev/lattenero/bot/daemon/bus/BusProducer.kt` — prompt, turn start, the call, its result, the turn's end, the turn's failure, plus the owner's 👍/👎 and redirect signals.
3. The contract: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/bus/BusEvent.kt` — the seven fields and the total parse.
4. The door into Postgres: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/bus/PgBusIngest.kt`, idempotent by id.
5. The pipeline: `agent-brain/core/src/main/kotlin/dev/lattenero/brain/bus/BusPipeline.kt` — ingest first, projection after, one handler behind either transport.

## 6 · Drill

Count what actually travels, straight from the file:

```nu
open --raw ~/.zcode/agent-brain/bus-events.jsonl
| lines | last 200 | each {|l| $l | from json } | get kind | uniq --count
```

Green when the counts name every kind the taps emitted, including `turn.feedback` and `correction` once the bots ship them. The failing case it rules out: trusting a tap that silently emits nothing — the file's counts are the only witness.
