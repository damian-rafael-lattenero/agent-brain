# B10 · Type classes

**Denotes.** An interface that carries LAWS, with instances written outside the types they serve — the contract is the methods plus the equations the methods must keep, and the generic code works on anything that has an instance.

## 1 · The aha

An interface says "these methods exist". A type class says "these methods exist AND these equations hold between them" — and that second half is what lets generic code compose behavior without knowing the type: the law is the contract's real content.

## 2 · What it denotes

In Haskell: `class Codec t where encode :: t -> String, decode :: String -> Maybe t` with the law `decode (encode x) == x` stated beside it, instances declared per type, and `roundTrip :: Codec t => t -> Maybe t` working for every instance forever. The language resolves instances globally and coherently: one per type, everywhere.

## 3 · In your languages

**Kotlin.** The nearest shape: an interface + explicit instances (objects) + a generic function constrained by the type parameter. The difference is coherence — two instances for one type CAN disagree, so every instance carries a law test of its own. Full row: `kotlin-kb/notes/canon-map.md`, `type-classes`.

**Nushell.** The instance as RECORD: a record of closures passed by hand — the dispatch-table pattern wearing the class's clothes. The shape check cannot catch a fake instance; only the law test travels with the record. Full row: `nushell-kb/notes/canon-map.md`.
