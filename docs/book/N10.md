# N10 · `proc.nu` — external processes as records

**Denotes.** The process-edge fold: whatever `complete` hands back, one function turns it into plain text — because the boundary's shape is not stable.

## 1 · The aha

`complete` is the boundary where externals hand their result back, and its `stderr` arrives as a STRING or a LIST OF LINES depending on how the external chunked its output (measured 15/11, duplicated in brain-doctor and brain). An error path that string-slices it blindly crashes on the list shape and HIDES the real error it was trying to show. One fold, everywhere, so the error path never crashes folding the very error it is reporting.

## 2 · What it denotes

`fold-stderr` (fold a `complete` record's stderr — string or list-of-lines — into one text; missing or null answers `""`). Verified: a record whose stderr is `['one', 'two']` folds to `one\ntwo`. The module is one function on purpose: the boundary has ONE honest shape and the fold is its name.

## 3 · In your languages

**Nushell.** This module — and the `cmd | complete` idiom from B24's row: stdout, stderr and exit_code as VALUES.

**Kotlin.** `ProcessBuilder` redirects a child's streams explicitly; kap's Process laws do the accounting (the process tree must survive the caller, which is why deploys run outside ZCode). The shared rule: never assume a stream's shape — redirect or fold it, name the type.
