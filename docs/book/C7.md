# C7 · The nightly cycle: the machine audits itself

**Denotes.** At 04:00 the fleet re-reads itself: refresh the index, check the corpus is English, run the real-questions suite, grade the served queries, judge the newest replies, record the fleet's numbers — and speak one honest line to Telegram.

## 1 · The aha

A system that indexes without measuring cannot say whether it got better. The nightly's law is simple: every morning there is a number, and a number below its bar speaks LOUD — silence is the failure, not the miss.

## 2 · What it denotes

The loop, one night (`agent-brain/scripts/rag-nightly.nu`): index the curated corpus, then the repos; export the store and run the English check — Spanish prose in the index fails the night, LOUD; run the real-questions suite; grade the production query log (the usage leg); judge the newest completed bot turns on the rubric (the shadow leg); record the fleet's numbers (the eval-numbers leg, U22). A failure in any leg does not abort the rest — the alarm speaks, the night continues.

Everything runs under launchd, outside any session: `com.zcode.agent-brain-index` fires at 04:00, and the helper plists keep the stack up. Jobs are threads: nothing of the night lives in a session's child tree.

## 3 · In your languages

**Kotlin.** The suite runner is the same idea in-process: one command, one report, one recorded row — the nightly calls the same binary the CLI does. Full row: `kotlin-kb/notes/canon-map.md`, `composition`.

**Nushell.** The night IS a Nushell script: legs as statements, each captured with `complete`, each degrading alone — a leg's failure prints and speaks but never aborts. The alarm goes through `Scripts/lib/deploy.nu`'s `announce` and `announce-loud`. Full row: `nushell-kb/notes/canon-map.md`, `composition`.

## 4 · In your system
